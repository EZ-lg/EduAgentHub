## 1. 项目概述

### 1.1 项目定位

为教培机构老板和教务人员提供一个**开箱即用的桌面工具**，以 **"AI 对话式采集 + 按学科管理"** 为核心模式，覆盖从新生咨询到结课归档的完整业务流程。

### 1.2 核心设计理念

| 理念 | 说明 |
|------|------|
| **AI 对话，不是填表** | 新建学科后，AI 动态对话式采集学情信息，追问到足够才生成报告 |
| **学科独立管理** | 每个学生可以有多个学科，每个学科有独立的报告、规划、成绩曲线 |
| **AI 辅助，人工决策** | AI 生成一切均可人工编辑，最终决策权在老师/教务 |
| **点开即用** | 每个功能独立入口，不需要写长 prompt |
| **数据本地化** | SQLite + ChromaDB 全本地，数据不出电脑 |
| **模型可替换** | 应用内切换不同大模型，不受单一厂商绑定 |
| **先 Web 后 EXE** | 开发阶段浏览器调试，成熟后打包为 exe |

## 2. 用户与使用场景

| 角色 | 职责 | 关注功能 |
|------|------|---------|
| **教务/咨询师** | 接待咨询、建档、AI对话采集、生成报告、管理沟通日志 | 学生档案、学科管理、AI报告、沟通日志 |

## 3. 核心业务流程

### 3.1 主线：从咨询到结课

```
【第1步：建档】
家长来咨询 → 教务点"新建学生" → 填写基本信息（姓名、学校、年级、电话、家长姓名）
→ 学生档案创建成功（无学科，无报告）

【第2步：新建学科 — AI 对话式采集】
点击学生卡片 → "新增学科" → 选择学科（如：数学）
→ 开启 AI 对话 ——

    AI："你好，XX同学想补习数学对吗？先了解一下，目前数学大概在什么分数段？"
    教务输入："大概60-70分，基础薄弱"
    AI："明白了。具体哪些章节觉得比较困难？比如函数、几何、还是计算？"
    教务输入："函数部分，特别是二次函数"
    AI："二次函数是中考重点。有没有最近一次考试的分数可以参考？"
    教务输入："期中考了65分，满分120"
    AI："目标是多少分？"
    教务输入："希望期末能到85分以上"
    AI："每周能安排几次课？每次多久？"
    教务输入："周末两天每天2小时"
    AI → [判断信息足够] → "好的，信息差不多了。还有什么要补充的吗？"
    教务："没有了"
    → 点击"生成报告" → AI 总结并生成【数学学情报告 + 课程规划】

【第3步：审核报告】
教务查看报告 → 编辑调整 → 导出 PDF 给家长 → 家长满意 → 报名

【第4步：新增其他学科】
学生在读期间 → 想加英语 → 点击"新增学科" → 选英语 → 新一轮 AI 对话 → 生成英语报告
每个学科独立管理：英语有英语的报告、规划、成绩曲线

【第5步：教学追踪】
每次考试 → 在对应学科下录入成绩 → 成绩曲线自动更新 → AI 分析趋势 → 调整课程规划

【第6步：停用学科】
数学不想补了 → 停用数学学科 → 历史数据保留可查看，不再活跃
以后想恢复 → 重新启用即可

【第7步：结课】
所有学科停用或完成 → 学生状态变为"结课" → 归档
```

### 3.2 支线：知识库维护

```
教务上传机构资料 → 自动切片入库(ChromaDB)
→ AI 生成报告时自动引用相关知识
→ 教务也可在"知识库问答"中直接提问，AI 基于知识库回答
```

## 5. 数据模型设计

### 5.1 数据关系

```
students (1) ──────< subjects (N)           ← 一个学生有多个学科
subjects (1) ──────< ai_conversations (N)   ← 一个学科有多次 AI 对话
subjects (1) ──────< reports (N)            ← 一个学科有多版报告
subjects (1) ──────< scores (N)             ← 一个学科有多条成绩
subjects (1) ──────< course_plans (N)       ← 一个学科有多版规划
subjects (1) ──────< communication_logs (N) ← 一个学科有多条沟通日志
reports (1) ───────< course_plans (N)       ← 报告关联的规划

teachers ────────── (独立，被课程规划引用)
knowledge_docs ──── (独立)
settings ────────── (独立，key-value)
activity_logs ───── (独立，关联 student_id / subject_id 可为空)
```

### 5.2 建表语句

```sql
-- ============================================================
-- 学生表
-- ============================================================
CREATE TABLE students (
    id              INTEGER PRIMARY KEY AUTOINCREMENT,
    name            TEXT NOT NULL,
    gender          TEXT DEFAULT '',
    grade           TEXT DEFAULT '',
    school          TEXT DEFAULT '',
    phone           TEXT DEFAULT '',
    parent_name     TEXT DEFAULT '',
    parent_phone    TEXT DEFAULT '',
    address         TEXT DEFAULT '',
    source          TEXT DEFAULT '',
    status          TEXT DEFAULT 'active',         -- active / completed / abandoned
    notes           TEXT DEFAULT '',
    created_at      TEXT NOT NULL,
    updated_at      TEXT NOT NULL
);

-- ============================================================
-- 学科表（核心实体）
-- ============================================================
CREATE TABLE subjects (
    id              INTEGER PRIMARY KEY AUTOINCREMENT,
    student_id      INTEGER NOT NULL,
    name            TEXT NOT NULL,                  -- 学科名称：数学/英语/物理/...
    status          TEXT DEFAULT 'active',          -- active / paused
    created_at      TEXT NOT NULL,
    updated_at      TEXT NOT NULL,
    FOREIGN KEY (student_id) REFERENCES students(id) ON DELETE CASCADE
);

-- ============================================================
-- AI 对话记录表
-- ============================================================
CREATE TABLE ai_conversations (
    id              INTEGER PRIMARY KEY AUTOINCREMENT,
    subject_id      INTEGER NOT NULL,
    messages_json   TEXT DEFAULT '[]',              -- [{role, content, time}, ...]
    status          TEXT DEFAULT 'in_progress',     -- in_progress / completed
    created_at      TEXT NOT NULL,
    updated_at      TEXT NOT NULL,
    FOREIGN KEY (subject_id) REFERENCES subjects(id) ON DELETE CASCADE
);

-- ============================================================
-- 报告表（挂学科下）
-- ============================================================
CREATE TABLE reports (
    id                  INTEGER PRIMARY KEY AUTOINCREMENT,
    subject_id          INTEGER NOT NULL,
    conversation_id     INTEGER,
    title               TEXT DEFAULT '',
    content_json        TEXT DEFAULT '{}',          -- {sections: {...}}
    course_plan_id      INTEGER,
    kb_references_json  TEXT DEFAULT '[]',
    status              TEXT DEFAULT 'draft',       -- draft / published
    created_at          TEXT NOT NULL,
    updated_at          TEXT NOT NULL,
    FOREIGN KEY (subject_id) REFERENCES subjects(id) ON DELETE CASCADE,
    FOREIGN KEY (conversation_id) REFERENCES ai_conversations(id) ON DELETE SET NULL,
    FOREIGN KEY (course_plan_id) REFERENCES course_plans(id) ON DELETE SET NULL
);

-- ============================================================
-- 考试成绩表（挂学科下）
-- ============================================================
CREATE TABLE scores (
    id              INTEGER PRIMARY KEY AUTOINCREMENT,
    subject_id      INTEGER NOT NULL,
    exam_name       TEXT DEFAULT '',
    score           REAL NOT NULL,
    total_score     REAL NOT NULL,
    exam_date       TEXT NOT NULL,
    notes           TEXT DEFAULT '',
    created_at      TEXT NOT NULL,
    FOREIGN KEY (subject_id) REFERENCES subjects(id) ON DELETE CASCADE
);

-- ============================================================
-- 课程规划表（挂学科下）
-- ============================================================
CREATE TABLE course_plans (
    id                  INTEGER PRIMARY KEY AUTOINCREMENT,
    subject_id          INTEGER NOT NULL,
    version             INTEGER DEFAULT 1,
    plan_json           TEXT DEFAULT '[]',          -- [{lesson, content, hours, teacher_id, schedule, notes}]
    status              TEXT DEFAULT 'active',      -- active / archived
    adjustment_reason   TEXT DEFAULT '',
    created_at          TEXT NOT NULL,
    FOREIGN KEY (subject_id) REFERENCES subjects(id) ON DELETE CASCADE
);

-- ============================================================
-- 沟通日志表（挂学科下）
-- ============================================================
CREATE TABLE communication_logs (
    id              INTEGER PRIMARY KEY AUTOINCREMENT,
    subject_id      INTEGER NOT NULL,
    method          TEXT DEFAULT '面谈',            -- 电话/微信/面谈/其他
    content         TEXT NOT NULL,
    log_time        TEXT NOT NULL,
    created_at      TEXT NOT NULL,
    FOREIGN KEY (subject_id) REFERENCES subjects(id) ON DELETE CASCADE
);

-- ============================================================
-- 教师表
-- ============================================================
CREATE TABLE teachers (
    id              INTEGER PRIMARY KEY AUTOINCREMENT,
    name            TEXT NOT NULL,
    phone           TEXT DEFAULT '',
    subjects        TEXT DEFAULT '',                -- JSON数组：["数学","物理"]
    intro           TEXT DEFAULT '',
    created_at      TEXT NOT NULL,
    updated_at      TEXT NOT NULL
);

-- ============================================================
-- 知识库文档表
-- ============================================================
CREATE TABLE knowledge_docs (
    id              INTEGER PRIMARY KEY AUTOINCREMENT,
    title           TEXT NOT NULL,
    category        TEXT DEFAULT '其他',
    file_path       TEXT DEFAULT '',
    file_type       TEXT DEFAULT '',
    chunk_count     INTEGER DEFAULT 0,
    status          TEXT DEFAULT 'active',          -- active / disabled
    created_at      TEXT NOT NULL
);

-- ============================================================
-- 系统设置表
-- ============================================================
CREATE TABLE settings (
    id              INTEGER PRIMARY KEY AUTOINCREMENT,
    key             TEXT NOT NULL UNIQUE,
    value_json      TEXT DEFAULT '{}',
    updated_at      TEXT NOT NULL
);

-- ============================================================
-- 操作日志表
-- ============================================================
CREATE TABLE activity_logs (
    id              INTEGER PRIMARY KEY AUTOINCREMENT,
    student_id      INTEGER,
    subject_id      INTEGER,
    action          TEXT NOT NULL,
    detail          TEXT DEFAULT '',
    created_at      TEXT NOT NULL,
    FOREIGN KEY (student_id) REFERENCES students(id) ON DELETE SET NULL,
    FOREIGN KEY (subject_id) REFERENCES subjects(id) ON DELETE SET NULL
);
```

### 5.6 为什么 SQLite + ChromaDB 足够

| 需求 | 数据量 | SQLite/ChromaDB 能力 | 结论 |
|------|--------|---------------------|------|
| 学生记录 | 几千条 | SQLite TB级 | ✅ |
| 学科记录 | 每生 1-5 个 | 无压力 | ✅ |
| AI 对话消息 | 每次几十条 | JSON 字段存储 | ✅ |
| 成绩记录 | 每学科几十条 | 索引毫秒级 | ✅ |
| 沟通日志 | 每学科几十条 | 无压力 | ✅ |
| 向量检索 | 几十~几百份文档 | ChromaDB 专为此设计 | ✅ |
| 并发 | 单用户桌面应用 | 单写锁完全无感 | ✅ |

> 不需要 MySQL / PostgreSQL / MongoDB。SQLAlchemy ORM 层让未来迁移成本很低。

   ┌────────────┐      ┌────────────┐      ┌────────────┐
   │  OpenAI    │      │  Claude    │      │  DeepSeek  │  ...

### 7.2 Provider 矩阵

| Provider | Chat | Embedding | 备注 |
|----------|------|-----------|------|
| OpenAI | ✅ | ✅ text-embedding-3-small | 格式最通用 |
| Claude | ✅ | ❌ 需单独配 | 分析深度最优 |
| 通义千问 | ✅ | ✅ text-embedding-v4 | 国内快、中文好 |
| DeepSeek | ✅ | ❌ | 性价比之王 |
| Moonshot | ✅ | ❌ | 中文长文本好 |
| 自定义兼容 | ✅ | ✅ | 接 Ollama/vLLM |

### 7.3 Embedding 方案：统一走 API

| 对比 | API Embedding | 本地模型 |
|------|-------------|---------|
| 费用 | 极低（百万token约¥0.1-0.5） | 免费 |
| 部署 | 零，填 Key 即用 | 需打包 ~1.5GB |
| 效果 | 大厂持续优化 | 也不错但重 |

> 先用 API，后续有离线需求再新增 `LocalEmbeddingProvider`。

### 7.4 AI 调用场景

| 场景 | 输入 | 知识库 | 输出 |
|------|------|--------|------|
| **AI 对话式采集** | 当前对话历史 + 学科信息 | ❌ | 下一条 AI 回复 + 是否该结束 |
| **生成报告** | 对话总结 + 学科信息 | ✅ 课程大纲+案例 | 4 节报告内容 + 课程规划 JSON |
| **成绩分析** | 成绩数组 | ✅ 课程大纲 | 趋势 + 薄弱点 + 建议 |
| **课程规划调整** | 当前规划 + 成绩分析 | ✅ 课程体系 | 调整后规划 JSON |
| **知识库问答** | 用户问题 | ✅ 知识库全文 | 回答 + 引用来源 |

### 7.5 RAG 检索流程

```
AI 生成报告 / 知识库问答
      │
      ▼
提取查询关键词
      │
      ▼
ChromaDB 向量检索 → Top-5 相关片段
      │
      ▼
拼接 Prompt：[System] + [知识库Context] + [User信息]
      │
      ▼
调用 LLM → 返回结果
```

## 11. 部署与打包方案

### 11.1 开发模式

```bash
pip install -r requirements.txt
python main.py
# → 浏览器自动打开 http://127.0.0.1:8888
```

### 11.2 打包

```bash
pyinstaller --onefile \
    --name "教培智能体" \
    --icon build/icon.ico \
    --add-data "frontend;frontend" \
    --add-data "backend/ai/prompts;backend/ai/prompts" \
    --collect-all chromadb \
    main.py
# → dist/教培智能体.exe
```

### 11.3 部署

```
拷贝 exe 到老板电脑 → 双击运行 → 首次在 exe 同级创建 data/ 文件夹
迁移数据 → 拷贝 data/ 文件夹
```

### 11.4 main.py

```python
import webbrowser, uvicorn, threading, socket, time

def find_free_port(start=8888):
    port = start
    while port < start + 100:
        with socket.socket(socket.AF_INET, socket.SOCK_STREAM) as s:
            if s.connect_ex(('127.0.0.1', port)) != 0:
                return port
        port += 1
    return start

def open_browser(url):
    time.sleep(1.5)
    webbrowser.open(url)

def main():
    port = find_free_port()
    url = f"http://127.0.0.1:{port}"
    threading.Thread(target=open_browser, args=(url,), daemon=True).start()
    uvicorn.run("backend.app:app", host="127.0.0.1", port=port)

if __name__ == "__main__":
    main()
```

## 13. 风险与待确认项

### 13.1 技术风险

| 风险 | 缓解 |
|------|------|
| ChromaDB 打包报错 | P2 后立刻试打包验证 |
| PDF 中文乱码 | 前端 jsPDF + html2canvas（浏览器自带字体） |
| AI 对话质量不稳定 | Prompt 持续调优；预留"重新生成"兜底 |
| exe 体积过大 | 预计 300-800MB，单机应用可接受 |

### 13.2 已确认决策

| # | 决策 |
|---|------|
| 1 | 先出报告，再试听（试听课算第一节课） |

| 3 | 沟通日志挂在学科下 |
| 4 | 每个学生档案独立，无家庭概念 |
| 5 | 全是 1v1，无班课 |
| 6 | 教师管理：姓名 + 擅长科目(多选) + 电话 + 简介 |
| 7 | 知识库问答：预设问题 + 自由提问 |
| 8 | AI 对话由 AI 判断结束，可手动提前结束 |
| 9 | 对话结束后不保留草稿 |
| 10 | 学科可停用（不删数据），可新增 |
| 11 | 预留 Excel 批量导入学生功能 |
| 12 | 大模型失败 → 重新生成即可 |
