## 一、项目概述

### 1.1 定位

为教培机构老板和教务人员提供的**开箱即用桌面工具**，以 **"AI 对话式采集 + 按学科管理"** 为核心模式，覆盖从新生咨询到结课归档的完整业务流程。本地运行、数据不出电脑，单 exe 免部署即开即用。

### 1.2 核心设计理念

| 理念 | 说明 |
|------|------|
| **AI 对话，不是填表** | 新建学科后 AI 动态对话式采集学情，追问到足够才生成报告 |
| **学科独立管理** | 每个学生多个学科，每学科独立的报告/规划/成绩/日志 |
| **AI 辅助，人工决策** | AI 生成的一切均可人工编辑，最终决策权在老师/教务 |
| **点开即用** | 每个功能独立入口，无需写长 prompt |
| **数据本地化** | SQLite + ChromaDB 全本地，数据不出电脑 |
| **模型可替换** | 应用内切换大模型，不受单一厂商绑定 |
| **先 Web 后 EXE** | 开发阶段浏览器调试，成熟后打包为 exe |

### 1.3 核心业务流程（三条主线）

```
建档 → 新建学科 → AI对话式采集 → 生成学情报告+课程规划 → 导出Word/PDF → 报名
教学 → 录入成绩 → 成绩曲线 → AI分析 → 课程规划调整 → 循环
知识 → 上传资料 → 自动切片入库(ChromaDB) → AI引用(RAG) + 智能问答
```

## 四、核心数据模型

### 4.1 数据关系

```
students (1) ──────< subjects (N)           ← 一个学生有多个学科
subjects (1) ──────< ai_conversations (N)   ← 一个学科有多次 AI 对话
subjects (1) ──────< reports (N)            ← 一个学科有多版报告
subjects (1) ──────< scores (N)             ← 一个学科有多条成绩
subjects (1) ──────< course_plans (N)       ← 一个学科有多版规划
subjects (1) ──────< communication_logs (N) ← 一个学科有多条沟通日志
reports (1) ───────< course_plans (N)       ← 报告关联的规划

teachers / knowledge_docs / settings / qa_history / activity_logs ── (独立)
```

**铁律**：报告、规划、成绩、日志全部挂在 `subjects` 下，不是直接挂 `students` 下。

### 4.2 表清单（共 12 张）

| 表 | 说明 | 关键字段 |
|----|------|---------|
| students | 学生 | name/gender/grade/school/phone/parent_*/address/source/status/notes |
| subjects | 学科（核心实体） | student_id/name/status |
| ai_conversations | AI 对话 | subject_id/messages_json/status |
| reports | 报告 | subject_id/conversation_id/title/content_json/course_plan_id/kb_references_json/status |
| scores | 成绩 | subject_id/exam_name/score/total_score/exam_date/notes |
| course_plans | 课程规划 | subject_id/version/plan_json/status/adjustment_reason |
| communication_logs | 沟通日志 | subject_id/method/content/log_time |
| teachers | 教师 | name/phone/subjects(JSON数组)/intro |
| knowledge_docs | 知识库文档 | title/category/file_path/file_type/chunk_count/status/index_status/index_error |
| qa_history | 问答历史（P8新增） | question/answer/references_json |
| settings | 系统设置 | key/value_json |
| activity_logs | 活动日志 | student_id/subject_id/action/detail |

> 需求文档 §5.2 原为 11 张表；P8 新增 `qa_history`（问答历史持久化），并对 `knowledge_docs` 增加 `index_status`/`index_error`（异步入库状态机）。

### 4.3 状态机

- **学生**：`active`（在读）→ `completed`（结课）/ `abandoned`（放弃）；`abandoned` → `active`（捞回）
- **学科**：`active`（活跃）⇄ `paused`（已停用）；停用≠删除，数据全保留
- **课程规划**：`active` ⇄ `archived`；每次变更新建版本并归档旧版
- **报告**：`draft` / `published`

### 4.4 关键 JSON 结构

- `ai_conversations.messages_json`：`[{role:"ai"|"user", content, time}]`
- `reports.content_json`（**最终为章式结构**）：
  ```
  {title, subtitle, summary, chapters[10], plan[], conclusion, kb_references}
  ```
  10 章固定：一、当前情况与目标 / 二、目标达成路径 / 三、核心战略 / 四、方法论科学原理 / 五、两阶段执行框架 / 六、本学科落地规划(+plan表格) / 七、学期节奏与每周安排 / 八、时间管理与精力保护 / 九、评估与复盘机制 / 十、心态建设。每章 `{title, content, ai_generated, last_modified}`。
- `course_plans.plan_json`：`[{lesson, content, hours, teacher_id, teacher_name, schedule, notes}]`

## 五、AI 服务层

### 5.1 适配器模式

```
AIManager（单例：get_llm / get_embedding / is_configured / reload_config）
   └── AIProviderFactory（PROVIDER_CLASSES 注册表）
         └── BaseLLMProvider（chat / chat_stream / embed / health_check / to_meta）
```

### 5.2 Provider 矩阵（实际实现 5 个）

| Provider | Chat | Embedding | 备注 |
|----------|------|-----------|------|
| openai | ✅ | ✅ text-embedding-3-small | 基线 |
| deepseek | ✅ | ❌ | 继承 OpenAIProvider |
| qwen | ✅ | ✅ | 通义千问 DashScope 兼容 |
| claude | ✅ | ❌ | Anthropic SDK，system 提取 + 同角色合并 |
| custom_openai | ✅ | ✅ | Ollama/vLLM 等 OpenAI 兼容 |

> deepseek/qwen/custom 均继承 `OpenAIProvider`，仅覆盖类属性，零重复代码。

### 5.3 Prompt 模板（12 个，Jinja2 StrictUndefined）

`conversation` / `conversation_end` / `report_generation` / `report_regenerate` / `course_planning` / `score_analysis` / `plan_adjustment` / `knowledge_qa` / `system_prompt` / `category_classify`（AI 自动分类）/ `query_rewrite`（问答改写）/ `student_chat`

> 模板变量必须全传（StrictUndefined 下缺变量直接报错，防静默缺字段）。

### 5.4 RAG 流程与唯一接入点

```
检索 Top-K → 拼 Prompt[System + 知识库Context + User] → LLM
```

- **唯一接入点**：`report_generator._retrieve_kb_context()`。报告生成、成绩分析、规划调整均复用此函数，P8 只替换了这一处实现即让全部 AI 场景自动受益。
- **优雅降级**：embedding 未配置 / 无 active 文档时返回空，报告照常生成。

## 六、关键技术架构决策汇总

| 决策 | 说明 |
|------|------|
| API 响应格式 | 统一 `{"success":true,"data":{...}}` / `{"success":false,"error":"..."}` |
| 时间格式 | 全部 ISO 字符串存储 |
| 路由参数 | `data: dict` 接收 JSON body（非 Pydantic），适合快速原型 |
| 前端模板 | 页面 HTML 经 `fetch()` 加载，缓存到 `templateCache`；Hash 路由 |
| 页面脚本执行 | v-html 不执行内联 `<script>` → `app.js` 的 `executeInlineScripts()` 手动重建执行 |
| 报告生成 | **手动触发**（对话结束点「生成报告」才调 AI），响应快、用户可控 |
| 报告结构 | 需求 4 节 → 最终改造为**章式 10 章**（按机构 Word 模板） |
| 报告导出 | PDF（jsPDF+html2canvas-pro 前端栅格化）→ **主打 Word**（`export_docx.py` python-docx 按模板排版） |
| AI 调整 | `/plans/adjust` **预览两步不落库**，用户核对后点「保存为新版本」才入库 |
| 规划版本纪律 | 任何变更（手动/回退/AI保存/报告页保存）新建版本+归档旧 active；`report.course_plan_id` 指向最新 |
| 回退 | 复制旧版内容追加新版本（reason「回退到 vX」），保持审计链 |
| RAG | 唯一接入点 + 优雅降级（见 §5.4） |
| 沟通日志 | 挂 subject 不挂 student |
| 前端缓存 | 后端 no-store 中间件 + `index.html` 版本自愈机制 |

## 七、开发纪律与踩坑记录（⚠️ 2.0 必须继承）

1. **版本号纪律（改前端必做）**：改任何前端文件后，同步递增 `index.html` 里 `window.APP_VERSION` + 所有 JS/CSS 引用的 `?v=`（当前 26）。版本变了浏览器自动强制刷新一次（自愈机制），忘了递增用户会看到旧代码。
2. **Tailwind 重编译纪律**：Tailwind 已本地编译（非 Play CDN）。新增 Tailwind class / 新页面后必须 `python build_tailwind.py` 重跑，否则新 class 静默无样式。CLI 在 `build/tools/`。
3. **IIFE 纪律**：所有页面脚本包 `(function(){...})()` + 末尾 `Object.assign(window,{...})` 导出（必须是 `function` 声明，不能 const 箭头函数）。否则 SPA 重复访问会 `Identifier already declared` 崩溃。
4. **SQLite 外键 PRAGMA**：`backend/models/__init__.py` 里 `PRAGMA foreign_keys=ON` 是级联删除的命根子，改动 models 时**不要移除**。
5. **数据模型铁律**：业务数据挂 `subjects`；删除学生级联删除学科及全部关联数据（不可逆，前端二次确认）。
6. **RAG 唯一接入点**：替换/升级检索只动 `_retrieve_kb_context`，别在调用方各写一套。
7. **ECharts 生命周期三件套**：IIFE 内 `let chart` + `disposeXxxChart` + 具名 resize handler + `window.__pageUnmounted` 注册（app.js `unmounted` 会调用）；Tab 重渲染前先 dispose。
8. **页面脚本执行**：新增页面内联脚本依赖 `executeInlineScripts` 机制，别假设 v-html 会自动跑 script。
9. **看门狗纪律**：6s 加载看门狗**不再对活页面自动整页刷新**（会打断打字/滚动）；仅脚本压根没执行时兜底 reload。页面数据失败应自行渲染错误/空态。
10. **Tab 分发器纪律**：学科详情加 Tab 务必走 `renderSubjectTab` 分发器 + `currentSubjectTab` 记忆，不要硬编码 `renderReportTab()`（否则切回窗口自动跳回「报告」）。
11. **规划编辑器刷新陷阱**：程序整体改 `planRows` 后，要么直接改 DOM，要么 `drawPlanTab(false)`（不回填旧值）；手动增删行才用默认快照保留。
12. **消息角色约定**：`messages_json` 存 `ai`/`user`，转 LLM 时映射 `assistant`/`user`。
13. **StrictUndefined 全传**：各 Prompt 模板声明的变量必须全传，未就绪传空串（`{% if %}` 空串为假）。
14. **删除即级联**：删学生/文档/教师均为不可逆操作，教师删除保留规划历史引用（显示为无主），符合「停用≠删除」理念。
15. **测试方法**：后端可用内存库 + mock LLM 快速回归；真实链路配 DeepSeek 验证；前端 CDP 真实浏览器驱动。
