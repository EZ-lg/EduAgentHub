## 三之二、验收后发现的 Bug 与修复（重要！）

**① SPA 全局作用域冲突 → 页面脚本重复声明崩溃（最严重，直接导致"生成报告一直加载中"）**
- 现象：对话页点「生成报告」→ 跳转报告页后**一直卡"加载中"**，顶部刷新无效
- 根因：hash 路由 SPA 下所有页面脚本共享全局作用域。conversation.html 和 report.html 都声明顶层 `const state`，导航到 report 页时二次声明抛 `SyntaxError: Identifier 'state' has already been declared` → report 页脚本整体挂掉；且 `window.currentPageRefresh` 残留旧页面，看门狗调它报 `Cannot read properties of null`，刷新无效
- **潜在通病**：任何带顶层 `const/let` 的页面重复访问也会触发（P3/P4 页有同样隐患）
- 修复：**所有页面脚本包 IIFE `(function(){...})()`** + 末尾 `Object.assign(window, {...onclick 函数})` 导出 + `window.currentPageRefresh` 赋值。涉及 conversation / report / student_detail / student_list / settings 5 页
  - student_list 的分页内联 `studentPage=Math.max(...)` 改为 `changePage(delta)` 函数（IIFE 内变量不可从 onclick 直接读写）
  - conversation 的 `generateReport()` 改 `generateReport(this)`（不再依赖全局 `event.target`，避免 undefined 卡死）
- 验证：CDP 真实浏览器驱动，对话→提前结束→生成报告→报告页 4 节渲染，无异常；5 页两轮 SPA 导航全部正常

**② 导航走后旧异步回调操作已卸载 DOM → 控制台 null 报错**
- conversation 页加 `pageAlive()` 守卫：异步（start/send/refresh）resolve 后若页面已卸载则放弃渲染

**③ CDN 可靠性：Vue/Vue Router 从 unpkg 换到 jsdelivr**
- 本机 unpkg 不可达（curl 超时），jsdelivr 稳定可达；两行 script src 改动，功能等价
- 打包（P9）时统一下载到 frontend/vendor/ 离线

**④ 对话页 UI 优化（用户要求"问答流畅舒服"）**
- style.css 新增 `.conv-msg-row / .conv-avatar / .conv-bubble / .typing-dots`：AI/教务头像圆 + 圆角气泡 + 时间戳 + 打字三连跳动效
- conversation.html：气泡渲染改造 + 输入框/发送按钮圆角渐变 + 消息区浅色背景 + 平滑滚动
