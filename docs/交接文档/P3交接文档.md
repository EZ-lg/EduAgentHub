## 三之二、P3 验收后发现的 Bug 与修复（重要！）

**① SQLite 外键未启用 → 级联删除失效 + ID 复用让新学生"继承"旧学科（最严重）**
- 现象：删除学生后学科残留；新建学生拿到复用 ID，直接显示旧学生的学科（用户报"新建完学生直接就有学科"）
- 根因：SQLite 默认 `foreign_keys=OFF`，`ON DELETE CASCADE` 不生效；且表没有 AUTOINCREMENT，删光后 ID 从 1 复用
- 修复：`backend/models/__init__.py` 加 `@event.listens_for(Engine, "connect")` 执行 `PRAGMA foreign_keys=ON`
- **⚠️ 任何新表的 FK 级联（reports/scores/plans/logs 等）都依赖这个 PRAGMA，P5-P9 必须保证它在！**

**② 前端静态资源缓存 → 用户浏览器用到旧文件，页面 JS 失效**
- 现象：用户每次都要手动 Ctrl+F5 才生效（"加载中不动"）
- 修复：`backend/app.py` 加中间件，对 `/`、`.html`、`.js`、`.css` 返回 `Cache-Control: no-cache, must-revalidate`
- 效果：浏览器每次重新校验，改动代码后无需手动刷新

**③ 弹窗升级为两列填表式**
- `Utils.showModal` 新增 `columns: 2`（两列网格）、字段支持 `section`（分组标题）、`full: true`（占整行）、`subtitle`（弹窗副标题）
- 学生表单按「基本信息 / 联系方式 / 其他信息」分组，640px 宽，一次填完

**④ 新增学科查重**
- 学生详情页加学科时，若已有同名字科 → `confirmDialog` 二次确认，避免误加重复学科（之前 DB 里出现过 3 个"数学"）

**⑤ 学生列表页加「↻ 刷新」按钮**

**⑥ 全局刷新 + 自动刷新（解决"加载中不动、要手动F5"）**
- `index.html` 顶部标题栏加常驻「↻ 刷新」按钮 → `window.refreshPage()`
- `app.js` 注册全局刷新机制：`window.refreshPage` + `visibilitychange` 监听（切回标签页自动刷新）
- 每个页面脚本末尾注册 `window.currentPageRefresh`（dashboard=loadDashboard、列表=loadStudents、详情=refreshStudentDetail）
- 后端 `no-store` 缓存策略 + `index.html` 版本自愈脚本（`APP_VERSION` 变了自动 `location.reload()` 一次）
- `app.js` 加载看门狗：页面卡在"加载中"超过 6 秒，自动重试 `currentPageRefresh()`，脚本没执行则强制刷新一次（`sessionStorage.ta_wdog` 防死循环）

**⑦ 前端资源加载统一带 `?v=APP_VERSION`**（页面 fetch + JS/CSS 引用），配合 no-store 彻底杜绝旧缓存
